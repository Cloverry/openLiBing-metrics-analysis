# 采集实现参考（脚本内部细节）

> 这份文档不是流程说明，SKILL.md 不引用其中的步骤编排。只有要**改采集代码**时才需要看。

## 一、归档结构（数据与 HTML 完全隔离）

```
out/
├─ archive/<年>/<年-月>/<日>/<开源组件名>/<流水线名>/
│    _manifest.json            目录清单（每步来源/口径/计数/文件 + records 索引）
│    step_1_lights.json        第 1 步 该流水线当日筛选结果
│    step_2_runs.json … step_6_records.json
│    records/run_<构建号>.json 单条执行记录（页面与 AI 分析的最小单位）
│    job_logs/  case_logs/  github_logs/     证据原文
├─ work/     第 1~6 步中间产物（每次重跑覆盖，归档后可丢）
├─ state/    run_pipeline.log、cache/collection.json
└─ html/     展示层（静态壳，不含业务数据，运行时读 archive/）
```

页面只走 `_manifest.json` → `records[]` → `records/run_*.json`，不读大汇总文件。

## 二、配置（config.json）

| 字段 | 说明 |
|---|---|
| `date_range.start/end` | 留空 = 前一个工作日单日；填写则按该区间（脚本直接筛，不经 AI） |
| `products` | `[]` = 全部开源组件；`["MindStudio","Ascend-CANN"]` = 只看指定组件 |
| `project_id_map` | 可选兜底：组件 → projectId（优先从汇总接口自动发现） |
| `analysis_policy.always_analyze` | 不看板值是否为 1、一律重算的组件（默认 `["vllm-ascend"]`） |
| `analysis_policy.scheduled_only` | 只采定时运行的组件（默认 `["vllm-ascend"]`） |
| `workday_overrides` | 工作日兜底：`holidays` / `extra_workdays`（自动优先用 timor.tech 节假日 API） |
| `chrome` | `debug_port`（9222）、`chrome_path`（留空自动探测 Chrome/Edge）、`user_data_dir`（留空复用日常登录态）、`start_url` |
| `collect` | 各接口分页与日志扫描阈值（默认够用） |
| `cache` | 增量采集缓存（`enabled` 默认 true，落 `out/state/cache/collection.json`） |
| `github` | 第 5c 步 GitHub Actions 取证：`token`（只有 github 平台流水线出现时才必需）、`api_base`、`repos` 兜底映射 |
| `agent` | 第 8 步任务书与 profile 路径 |

## 三、采集步骤（第 1~7、9 步，全部脚本）

| 步骤 | 脚本 | 干什么 |

| 4 | `steps/step_4_testreport.py` | T6 失败用例 + 用例日志下载（全文件扫描带行号） |
| 5 | `steps/step_5_logs.py` | E 导出整 job 全量日志落盘 + 错误行扫描（T5 分页兜底） |
| 5b | `steps/step_5b_subtasks.py` | buildflow 失败子任务下钻（flow → build-log/export → build/log 兜底） |

## 四、接口速查（同源 fetch，实测通过）

鉴权：请求头 `Csrf-Token-Open-Li-Bing` = cookie `csrf-token-open-li-bing`；用例日志为 OBS 直链，免鉴权。

| 编号 | 用途 | 路径 | 关键参数 |
|---|---|---|---|
| T1 | 产品清单发现 | `POST /gateway/openlibing-ops/manage/ops-overview/main` | `{startDate,endDate,page,pageSize<=100}`，记录自带组件级双指标 |
| N1 | 夜间统计明细 | `POST /gateway/openlibing-ops/manage/common/detail` | `{category:'ops-nightly-detail',projectId,startDate,endDate,page,pageSize}`；`projectId` 必填 |
| N2 | 看板执行记录（唯一来源） | 同上 | `{category:'nightly-dashboard-detail',projectId,pipelineId,startDate,endDate,page,pageSize:100}` |
| T4 | 运行详情（失败任务） | `GET /gateway/openlibing-cicd/project/pipeline/pipeline-run/detail` | query 三参数 `projectId/pipelineId/pipelineRunId` |
| E | 整 job 全量日志导出 | `POST .../exec-log/export` → `GET /gateway/openlibing-framework/export/detail` → `/export/download-url` | 创建带 `lastDispatchId`；直链 OBS，Python 直接下载 |
| T5 | 任务日志（兜底） | `POST /gateway/openlibing-cicd/project/pipeline/logs` | `{...,sort:'desc',limit:300,startOffset,endOffset}`；400 页/24MB 上限 |
| T6 | 测试结果/失败用例 | `POST /gateway/openlibing-cicd/project/pipeline/test-report` | `state:['failed']` 必须是数组；`pageNumber/pageSize` |
| F | buildflow 子任务列表 | `GET /gateway/openlibing-cicd/project/pipeline/flow` | query `projectId/pipelineId/pipelineRunId/stepRunIds`；普通流水线返回空 |
| B1 | 子任务全量日志导出 | `POST .../build-log/export` | `jobId` 必须是 T4 失败步骤 `inputs[].key='jobId'` 的构建 jobId |
| B2 | 子任务日志兜底 | `GET .../build/log` | 缺 `buildNo` 报 4010102；`sort=DESC` 取尾部 |
| GH | GitHub Actions 取证 | `GET {api_base}/repos/{repo}/actions/runs/{rid}/jobs` + `/jobs/{id}/logs` + `/runs/{rid}/logs` | `Authorization: Bearer <token>`；logs 302 → blob |

新增接口的逆向方法：业务 JS（`/build/assets/index-*.js`）内含全部网关路径常量，静态 grep `/project/pipeline/` 或 `category` 即可，不需要抓包。

## 五、陷阱（踩过的坑）

1. `T6` 的 `state` 必须是数组 `['failed']`，`stepRunIds` 是逗号字符串；`T5` 的 `stepRunId` 是单个字符串。
2. `DEV-CODECI-35002` 是封装码，只定位层不定位因；真实报错多数在整 job 全量日志里可见，buildflow 任务必须下钻失败子任务日志。
3. flow 的 `builds[].id` 不能当 B1 的 `jobId`（传了报 500「构建任务不属于该流水线运行实例」）；`buildNo` 取 `builds[].build_no`，不是运行号。
4. 用例日志 HTML 报错提取，行正则要允许 `<tr class="...">`；>4MB 只扫尾部即可命中 `Test FAILED:`/`Traceback:`。
5. GitHub 侧取消 job 的日志可能未留存（blob 404），此时按 jobs 元数据定性并标注证据不完整；长 matrix job 名在 ~95 字符处被 `...` 截断，zip 条目名需净化（`/`→`_`、去引号/换行）。
6. `versionAvail` / `buildSuccess` 由服务端按工作日算好，前端只转百分比；不得用日历天数自行重算。
7. CDP `Runtime.evaluate` 里的顶层 `const` 会驻留页面全局环境，二次运行同名声明直接 `SyntaxError`；`cdp_exec.run_page_js` 已包进 async IIFE，自写脚本要守同一规则。
8. 必须走同源 fetch（CDP 在已登录页面执行），不要脱离浏览器 curl。

## 六、退出码

`0` 成功；`42` 正常提前结束（无待分析数据）；其他 = 失败，按 `--from` 续跑。
